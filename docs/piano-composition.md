# Piano Composition — 피아노 작곡

피아노 작곡은 악기 물리학, 손 해부학, 텍스쳐 문법을 동시에 만족해야 한다. AXIOM의 pianoIR, pianoProjection, pianoRepairSolver가 이 기준을 계산하고 수정한다.

---

## 1. Hand Playability — 손 연주 가능성

### 1.1 손 간격 (Hand Span)

| 범위 | 반음 수 | 평가 |
|------|--------|------|
| 옥타브 이하 | 0–12 | ✅ 항상 안전 |
| 단9도 (마이너 9th) | 13 | ✅ 작은 손도 가능 |
| 장9도 (메이저 9th) | 14 | ⚠ 주의, 일부 연주자 불가 |
| 10도 | 15–16 | ⚠ 큰 손만 가능 |
| 장10도 이상 | 17+ | ❌ 대부분 연주 불가 |
| 단13도 이상 | 19+ | ❌ 연주 불가 (분산 필수) |

AXIOM 지표:
- `pianoHandSpanViolations`: 19반음(단13도) 초과 개수 → 0이어야 함
- `pianoAwkwardSpanCount`: 14반음(장9도) 초과 누적 → 낮을수록 좋음

해결 전략:
- **분산 화음 (Arpeggio)**: 동시 연주 대신 순차 연주
- **보이싱 조정**: 중간 음을 제거하거나 옥타브 이동
- **분할 (Split)**: 왼손–오른손 분담 재배치

### 1.2 손 교차 (Hand Crossing)

두 손이 교차하는 기법은 의도적일 때만 사용:

| 상황 | 평가 |
|------|------|
| 음악적 효과를 위한 의도적 교차 | ✅ (악보에 명시) |
| 레지스터 배분 실수로 인한 교차 | ❌ 수정 필요 |
| 연속적 교차 | ❌ 연주 불가 |

AXIOM `pianoHandCrossingCount`: 비의도적 교차 수.

### 1.3 도약 (Leap) 관리

```
오른손 안전 도약: 단10도 이하
왼손 안전 도약: 장6도 이하 (베이스 라인은 더 엄격)
```

**왼손 베이스 도약 원칙**:
- 옥타브 도약: 허용 (표현적 효과)
- 10도 이상 연속 도약: 연주 어려움
- 빠른 템포에서 큰 도약: 정확성 감소

### 1.4 손가락 교체 (Finger Substitution)

같은 건반을 다른 손가락으로 교체하는 기법. 느린 선율에서 사용. 빠른 패시지에서는 어색함.

## 2. Texture Grammar — 텍스쳐 문법

### 2.1 기본 피아노 텍스쳐 유형

| 텍스쳐 | 설명 | 대표 패턴 |
|--------|------|---------|
| **Melody + Bass** | 오른손 선율 + 왼손 베이스 | 간단한 소품 |
| **Melody + Accompaniment** | 오른손 선율 + 왼손 화음/분산화음 | 낭만 스타일 기본 |
| **Alberti Bass** | 왼손 분산화음 (low-high-mid-high) | 고전 소나타 표준 |
| **Stride Bass** | 왼손 베이스-화음 교대 | 재즈/19세기 댄스 |
| **Chorale** | 4성부 합창 배치 | 장엄, 코랄 스타일 |
| **Counterpoint** | 두 손이 독립적 선율 교환 | 바로크, 인벤션 스타일 |
| **Broken Chord** | 분산화음 패턴 다양화 | 리스트, 쇼팽 스타일 |
| **Tremolo** | 빠른 반복 | 극적 긴장 |
| **Octave Melody** | 옥타브 병행 선율 | 강력한 주제 제시 |

### 2.2 Alberti Bass

고전 소나타의 가장 일반적 반주 패턴:

```
왼손 패턴:
  C₃  G₃  E₃  G₃  C₃  G₃  E₃  G₃
  (저음) (고음) (중음) (고음) ...
```

사용 원칙:
- 빠른 악장(Allegro)에서 적합
- 느린 악장에서는 단조로울 수 있음
- 같은 패턴이 너무 오래 지속되면 기계적
- 화성이 바뀔 때 자연스럽게 패턴 변형

### 2.3 텍스쳐 전환 원칙

텍스쳐는 구조와 연동되어야 한다:

| 섹션 역할 | 권장 텍스쳐 |
|----------|----------|
| 도입 (Intro) | 단순, 명확 (melody+bass 또는 chorale) |
| 주제 (Theme A) | 표준 melody+accompaniment |
| 브릿지/전환 | 텍스쳐 변화로 방향 전환 신호 |
| 개발부 (Development) | 대위법, 분열, 텍스쳐 불안정 |
| 절정 (Climax) | 옥타브 선율, 풍부한 화음 |
| 재현부 (Recap) | 주제 텍스쳐 복귀 (+ 옵션: 장식 추가) |
| 코다 (Coda) | 단순화 또는 확대 |

## 3. Voicing — 보이싱 (음 배치)

### 3.1 폐쇄 배치 vs 개방 배치

**폐쇄 배치 (Close voicing)**:
```
C E G C  (옥타브 안에 모든 음)
효과: 밀집된 느낌, 짧은 악절, 카덴츠
```

**개방 배치 (Open voicing)**:
```
C  G  E  C  (음 사이 간격 큼)
효과: 공간감, 장엄함, 오케스트라 느낌
```

### 3.2 선율 성부 위치

- **최고성부 선율**: 가장 일반적, 청자가 선율을 쉽게 따라감
- **내성부 선율 (inner melody)**: 낭만 스타일, 오른손 엄지나 왼손으로 선율, 나머지는 반주
- **베이스 선율**: 대위법, 인벤션 스타일

### 3.3 성부 진행 원칙

| 원칙 | 설명 |
|------|------|
| 최소 이동 | 각 성부는 최소한의 음정 이동 |
| 공통음 보유 | 연속 화음이 공통음을 같은 성부에 |
| 반행/사행 선호 | 두 성부가 반대 방향 또는 독립적으로 |
| 병행 8도/5도 회피 | 성부 독립성 파괴 |
| 성부 교차 회피 | 소프라노가 알토보다 낮아지는 것 |

AXIOM `pianoParallelOctaveCount`: 병행 옥타브 수.

### 3.4 피아노 성부 간 거리

```
[오른손 최고음]───┐
                  ├─ 두 손 간격 유지 권장: 메이저 3rd 이상
[오른손 최저음]───┤
                  ├─ 두 손이 겹치면 등록 분리 문제
[왼손 최고음]─────┘
[왼손 최저음]
```

AXIOM `pianoRegisterSeparation`: 성부 간 거리 측정.

## 4. Pedal — 페달 사용

### 4.1 서스테인 페달 (Right Pedal)

**역할**: 음을 지속, 화성 공명, 레가토 연결

**기본 규칙**:
- 화성이 바뀔 때 페달 교체 (화성 오염 방지)
- 베이스 음이 바뀌면 페달 교체
- 빠른 패시지에서 페달 과다 사용 금지 → 뭉침

**표현적 페달**:
- 장기 페달: 화성 혼합으로 인상주의 효과 (들뷔시 스타일)
- 짧은 페달: 스타카토 음을 약간 연결

### 4.2 소프트 페달 (Left Pedal, Una Corda)

피아노에서 약한 음색, 명상적 분위기. 과사용 금지.

### 4.3 AXIOM 페달 표시

현재 ExpressionPlan에서 직접 페달 표시를 생성하지 않음. 향후 구현 목표:
```typescript
interface PedalMarkings {
  pedalDown: number;   // measure number
  pedalUp: number;
  type: "sustain" | "soft";
}
```

## 5. Difficulty — 난이도

### 5.1 난이도 척도 (RCM/ABRSM 참고)

| 수준 | 특징 | AXIOM 대응 |
|------|------|-----------|
| 초급 (Grade 1–2) | 5음 음형, 간단한 리듬, 좁은 음역 | `difficulty: "beginner"` |
| 중급 (Grade 3–5) | Alberti bass, 1옥타브 이내 선율, 간단한 전조 | `difficulty: "intermediate"` |
| 중상급 (Grade 6–7) | 손 교차, 빠른 스케일, 조성 전환 | `difficulty: "advanced"` |
| 상급 (Grade 8+) | 복잡한 폴리포니, 큰 도약, 복잡한 리듬 | `difficulty: "virtuoso"` |

### 5.2 난이도 기여 요소

| 요소 | 설명 |
|------|------|
| 템포 | 빠를수록 어려움 |
| 손 간격 | 10도 이상 옥타브 주법 |
| 리듬 복잡도 | 두 손 다른 박자 (3 vs 2) |
| 조성 | 샵/플랫이 많을수록 어려움 |
| 도약 빈도 | 빠른 도약 연속 |
| 페달 타이밍 | 정확한 페달 교체 요구 |

### 5.3 AXIOM 난이도 제어

`ComposeRequest.qualityPolicy`에 `targetDifficulty` 추가 권장:
```typescript
interface QualityPolicy {
  targetDifficulty?: "beginner" | "intermediate" | "advanced" | "virtuoso";
  // pianoRepairSolver가 이 기준으로 수정 강도 결정
}
```

## 6. Common Mistakes AXIOM Must Avoid

| 실수 | 증상 | 수정 |
|------|------|------|
| 극단적 음역 사용 | C8 이상, A0 이하 음 생성 | 음역 클리핑 |
| 너무 빠른 베이스 도약 | 빠른 템포에서 10도 이상 왼손 도약 | 보이싱 재배치 |
| 두 손이 같은 음역 | 오른손/왼손 음역 중첩 | 등록 분리 |
| 모든 박자에 화음 | 선율 없는 순수 화음 진행 | 선율성 추가 |
| 손 교차 미표시 | 손 교차가 필요한데 악보에 없음 | 교차 필요 없는 보이싱으로 변경 |
| 텍스쳐 단일화 | 전 악장 알베르티 베이스 | 텍스쳐 전환 계획 |
| 너무 많은 스타카토 | 레가토 선율 없이 단편화 | 선율 구간 명시 |

## 7. AXIOM 현재 구현 상태

| 개념 | 현재 지원 | 목표 |
|------|---------|------|
| 손 간격 검사 | ✅ `handSpanViolations`, `awkwardSpanCount` | 임계값 조정 |
| 손 교차 감지 | ✅ `handCrossingCount` | 의도적 교차 허용 마킹 |
| 병행 옥타브 | ✅ `parallelOctaveCount` | 의도적 옥타브 선율 예외 처리 |
| 텍스쳐 계획 | 부분적 (`TextureGuidance`) | 섹션별 텍스쳐 패턴 명시 |
| 보이싱 검사 | ❌ | 성부 간 거리 + 병행 5도 |
| 페달 표시 | ❌ | ExpressionPlan 확장 |
| 난이도 제어 | ❌ | `targetDifficulty` 파이프라인 |
| Alberti bass 감지 | ❌ | 패턴 인식 + 과다 사용 제한 |
