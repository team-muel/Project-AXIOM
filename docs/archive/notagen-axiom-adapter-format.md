# NotaGen AXIOM Adapter – Data Format & Architecture

## Two-Stage Architecture

### Stage 1 (current): Generate → Select

```
AXIOM control block
    │
    ▼
NotaGen native engine  ─── many candidates ───► craft scoring + reranking
                                                        │
                                                        ▼
                                               selected + approved ABC
```

AXIOM plans the composition (section plan, cadence, texture, harmonic targets) and
converts it into a symbolic backend prompt.  NotaGen produces multiple ABC score
candidates.  AXIOM evaluates each candidate with craft scoring, reranks them via a
trained preference model, and a listener approves the best one.

The key limitation: NotaGen only receives `period / composer / instrumentation`
metadata, not the full AXIOM structural plan.  Control adherence is enforced
*after* generation.

### Stage 2 (target): Fine-tuned AXIOM-control-following adapter

```
AXIOM control block
    │
    ▼
fine-tuned adapter (LoRA on top of HF causal LM)
    │
    ▼
AXIOM-control-following ABC score
```

A fine-tuned adapter is trained on (control block → approved ABC) pairs collected
from Stage 1.  After fine-tuning the adapter understands the full AXIOM control
vocabulary and generates structurally compliant candidates on the first pass.

## SFT Training Data Format

Produced by `npm run export:notagen-sft`.

Output: `outputs/_system/ml/notagen-sft/<snapshot>/sft-pairs.jsonl`

Each line is a JSON object:

```json
{
  "id": "<sha256 hash of (songId, planSignature, generationMode)>",
  "songId": "song-abc123",
  "planSignature": "sig-def456",
  "generationMode": "notagen_abc_inference_hf_causal_lm",
  "instruction": "<conditioningText>\n%%axiom_control_begin\nperiod=Romantic\ncomposer=Brahms, Johannes\n...\n%%axiom_control_end",
  "output": "X:1\nT:Quartet in C minor\n...<full ABC score>...",
  "meta": {
    "provider": "notagen_local",
    "model": "notagen-v1",
    "normalizationWarnings": [],
    "craftScoreSummary": {
      "syntaxValidity": 0.95,
      "sectionContractFit": 0.82,
      ...
    }
  }
}
```

### Fields

| Field | Type | Description |
|---|---|---|
| `id` | string | Stable row hash for deduplication |
| `songId` | string | AXIOM song identifier |
| `planSignature` | string \| null | Hash of the composition plan |
| `generationMode` | string | Backend + engine identifier |
| `instruction` | string | Full AXIOM control prompt fed to the backend |
| `output` | string | Full ABC score text (X:1 header + body) approved by listener |
| `meta.craftScoreSummary` | object | Per-dimension craft scores at export time |

### Quality filter

Use `--min-score=<0.0-1.0>` to exclude rows whose average craft score is below the
threshold.  Default is `0.0` (all approved rows included).

Mock-backend rows (`generationMode` contains `"mock"`) are excluded by default.
Pass `--include-mock` for testing.

## Prompt Format

The same Alpaca-style template is used at **training** and **inference** time so the
model sees identical formatting in both contexts:

```
### Instruction:
{conditioning_text}
%%axiom_control_begin
period=Romantic
composer=Brahms, Johannes
instrumentation=String_Trio
section=1/4 exposition T:Exposition
cadence=HC
texture=homophonic
energy=0.7
...
%%axiom_control_end

### Response:
X:1
T:...
M:4/4
...
```

## Control Line Vocabulary

Control lines appear inside `%%axiom_control_begin … %%axiom_control_end` blocks.
They are generated by `workers/composer/learned_symbolic/abc_conditioning.py`.

| Key | Example value | Source |
|---|---|---|
| `period` | `Romantic` | promptPack.styleCue |
| `composer` | `Brahms, Johannes` | promptPack.styleCue |
| `instrumentation` | `String_Trio` | promptPack.styleCue |
| `meter` | `3/4` | compositionPlan |
| `section` | `1/4 exposition T:Exposition` | section plan |
| `cadence` | `HC` | section plan |
| `texture` | `polyphonic` | section plan |
| `energy` | `0.75` | section plan |
| `density` | `0.6` | section plan |
| `rewrite_target` | `section-2` | revision directives |

## Training

```bash
# 1. Export SFT pairs from approved candidates
npm run export:notagen-sft

# 2. Full fine-tuning (small model, CPU/GPU)
python scripts/train-notagen-axiom-adapter.py --snapshot=2025-05-15

# 3. LoRA fine-tuning (recommended for GPU)
python scripts/train-notagen-axiom-adapter.py \
    --snapshot=2025-05-15 \
    --mode=lora \
    --min-score=0.65
```

Output directory: `outputs/_system/ml/notagen-adapter/<run-id>/`

```
adapter_model/      HuggingFace model or LoRA adapter weights
run_summary.json    training config, loss, dataset stats
```

## Inference with fine-tuned adapter

At inference time (Stage 2), swap `NOTAGEN_ENGINE=hf_causal_lm` and point
`NOTAGEN_MODEL_PATH` at the adapter directory.  The `notagen_backend.py` prompt
builder already produces the same Alpaca-format prompt used during training.

```bash
NOTAGEN_ENGINE=hf_causal_lm \
NOTAGEN_MODEL_PATH=outputs/_system/ml/notagen-adapter/<run-id>/adapter_model \
npm start
```

## ABC Sidecar Storage

When the symbolic backend produces ABC text, it is stored as a sidecar file
alongside the MIDI and section artifacts:

```
outputs/<songId>/candidates/<candidateId>/
  candidate-manifest.json    structured evaluation + proposalEvidence
  composition.mid            rendered MIDI
  section-artifacts.json     per-section evaluation detail
  score.abc                  ← full ABC score text (SFT training target)
```

`candidate-manifest.json` references the sidecar via `artifacts.abc`.  The SFT
export script reads `proposalEvidence.abcText` directly from the manifest (the ABC
text is also stored inline there for convenience).

## Notes on NotaGen native weights

The NotaGen native engine (`NOTAGEN_ENGINE=notagen_native`) uses a custom
hierarchical decoder (Patchilizer + patch-level GPT) that is **not** compatible
with HuggingFace `AutoModelForCausalLM`.  The LoRA training script targets
HF-compatible causal LM checkpoints only.

For native NotaGen weights, adapt the official training loop from
https://github.com/ElectricAlexis/NotaGen using the SFT JSONL as the data source.
